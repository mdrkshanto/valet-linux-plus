01 / The idea

What is Valet Linux+?

Valet Linux+ configures your system to run Nginx in the background on boot. Using Dnsmasq, it routes every request for the *.test domain to projects on your machine. PHP requests are handed to PHP-FPM through per-version sockets.

It is not a replacement for Vagrant or Homestead — it is a faster, lighter alternative for developers who want flexible basics and extreme speed. It is the Linux continuation of the original Laravel Valet idea, packaged as genesisweb/valet-linux-plus.

Built for Linux firstUnlike ports of macOS Valet, this project natively supports apt, dnf, yum, pacman, eopkg and PackageKit, plus systemd and SysV-style service management.

Regarding SELinux

Fedora users should know how to configure or relax SELinux while Valet writes system files, otherwise changes may be blocked. The simplest approach is permissive mode:

sudo setenforce 0

Permanently: edit /etc/selinux/config, change SELINUX=enforcing to SELINUX=permissive, then reboot. If you intentionally want to skip the check during install, use valet install --ignore-selinux.

Arch Linux

RequirementValue
OS packagespacman -S nss jq xsel networkmanager ca-certificates
PHP version8.2+
PHP extensionspacman -S php-cli php-curl php-mbstring php-xml php-zip php-posix

Composer & the CLI helper

Composer must be installed (see getcomposer.org). The wrapper script also checks for jq, xsel and certutil before commands that need them — a missing dependency stops the command with an explicit message.

Regarding sudo and root

Valet automatically uses sudo for tasks that need it — your user must be a sudoer. Never install Valet as root or with sudo composer global require. Run Composer as your normal user; the valet wrapper elevates only the commands that need it.

Supported package managers

Installer logic ships for {{ pm }}, . Service management is handled through systemd or the Linux service manager abstraction.

Installation

Three commands from a clean Linux install to a working .test development environment.

Step 1 — Install the package

Install Valet Linux+ globally with Composer as your regular user:

composer global require genesisweb/valet-linux-plus

To update later: composer global update genesisweb/valet-linux-plus -W, or simply run valet update.

Step 2 — Add Composer's bin directory to PATH

Add the following to ~/.bash_profile or ~/.bashrc (adjust for zsh: ~/.zshrc):

export PATH="$PATH:$HOME/.config/composer/vendor/bin"
 
source ~/.bashrc

Step 3 — Run the installer

This configures and starts Nginx, PHP-FPM, Dnsmasq, Mailpit, Redis and your database, installs ngrok, creates the valet symlink and registers the daemon at boot.

valet install

valet install --mariadb

Use MariaDB instead of MySQL.

valet install --ignore-selinux

Skip the SELinux pre-flight check.

The installer asks whether to link Valet's PHP helper to /usr/local/bin/php. Accepting gives you a CLI that automatically follows the PHP version isolated for the directory you are in.

Step 4 — Verify DNS

Ping any *.test domain — it should resolve to 127.0.0.1:

ping -c1 foobar.test

If it does not respond, restart your machine (or restart the dnsmasq service) and try again.

Step 5 — Serve your first site

mkdir -p ~/sites
cd ~/sites && valet park
mkdir example && cd example
echo "<?php echo 'Valet Linux+ at your service';" > index.php
valet open
Install once, forget about itValet starts its services automatically at boot. There is no need to run valet start or valet install again after the initial setup.

Logs and diagnostics

Valet logs live in ~/.config/valet/Log. Use valet status for PHP-FPM and Nginx status, and valet which inside a project to see which driver is serving it.

valet status
valet which
valet paths
tail -f ~/.config/valet/Log/nginx-error.log

Guides

Serving sites

Park a folder and every project inside it becomes a .test site automatically. No per-site config, no hosts file.

Park a projects directory

mkdir ~/sites
cd ~/sites && valet park

Now any directory inside ~/sites is served at http://folder-name.test. For example:

mkdir ~/sites/example
cd ~/sites/example
echo "<?php echo 'Valet Linux+ at your service';" > index.php
valet open

Manage parked paths

CommandWhat it does
valet park [path]Registers the current directory (or the given path) as a projects root.
valet pathsDisplays every registered path in a table.
valet forget [path]Removes the current directory (or given path) from the paths list.
valet whichShows the driver assigned to the current directory.
valet open [domain]Opens the current (or given) site in your browser via xdg-open.

Domain aliases with symbolic links

Use links when a project lives outside a parked path, or when you want a second domain for it.

valet link                 # link current directory using its folder name
valet link yourproject2    # create yourproject2.test
valet links                # list URL, SSL and target path
valet unlink yourproject2  # remove the link

Customise the domain and ports

valet domain            # show the current domain (default: test)
valet domain local      # switch to *.local and re-secure sites
valet port              # show HTTP and HTTPS ports (80 / 443)
valet port 8080         # change the HTTP port
valet port 8443 --https # change the HTTPS port

Changing the domain automatically re-issues secured site certificates. Changing a port regenerates secure configs and restarts Nginx and PHP-FPM.

Automatic cleanupOn every command Valet prunes stale links and paths that no longer exist, so the table stays accurate when you delete projects.

Guides

Securing sites with TLS

Sites are served over HTTP by default. One command gives a site a trusted local TLS certificate and HTTP/2 support.

Secure and unsecure

valet secure example        # https://example.test with a trusted cert
valet secured example       # check whether a site is secured
valet unsecure example      # back to plain HTTP, certificate removed

Running valet secure or valet unsecure without a domain uses the current directory's name. Certificates are stored in ~/.config/valet/Certificates with the local CA in ~/.config/valet/CA.

Certificate lifecycle

  • valet domain newdomain re-secures every site for the new TLD automatically.
  • valet port 8443 --https regenerates all secured site configs for the new HTTPS port.
  • valet proxy domain http://host --secure creates a secured proxy with a trusted certificate.
  • valet isolate 7.4 --secure creates an isolated site with TLS enabled.

Browser trust

The generated CA must be trusted by your browser for the green padlock. On Firefox you may need to add the CA manually; older Ubuntu releases require the nginx PPA for HTTP/2 as noted in Requirements.

Where configs livePer-site Nginx configs — plain, secured, isolated and proxy variants — are written to ~/.config/valet/Nginx and included by the main Valet Nginx config.

Proxying local ports

Preview a Node, Docker, Vite or any other local service on a friendly .test hostname — optionally with HTTPS.

Create a proxy

valet proxy test http://localhost:3000
# http://test.test now forwards to localhost:3000

The host must be a valid http:// or https:// URL. If the domain does not already end with your Valet TLD it is appended for you.

valet proxy api http://127.0.0.1:8080 --secure
# https://api.test → http://127.0.0.1:8080 with trusted TLS

PHP

Switching PHP versions

Change the PHP version used by the whole environment, or keep global PHP untouched and isolate a single site.

Add a PHP repository firstValet downloads PHP versions through your distribution's extra repository. Without it, valet use cannot install the requested version.

Supported versions

ScopeVersionsCommand
Global FPM8.2, 8.3, 8.4, 8.5valet use
Per-site isolation7.0, 7.1, 7.2, 7.3, 7.4, 8.0, 8.1, 8.2, 8.3, 8.4, 8.5valet isolate

Older documentation mentions only 8.2 and 8.3 for valet use; the current 2.0.x source accepts 8.2 through 8.5. Anything older belongs in an isolated site.

Add the PHP repository

sudo add-apt-repository ppa:ondrej/php
sudo apt-get update

For Arch Linux, edit /etc/pacman.conf and add the repository before others that provide PHP:

[home_el_archphp_Arch]
Server = https://download.opensuse.org/repositories/home:/el:/archphp/Arch/$arch

Switch the global version

valet use 8.2                 # switch PHP-FPM for all sites
valet use 8.3 --update-cli    # also switch the default CLI PHP
valet use 8.4 --ignore-ext    # use the selected version's extensions
valet use                     # reset to the system default PHP

The --update-cli flag keeps your terminal's php -v in sync with the web server. The installer can also link a helper at /usr/local/bin/php that follows isolated directories automatically.

Configuration locations

  • FPM config: /etc/php/{version}/fpm/pool.d/valet.conf
  • php.ini: /etc/php/{version}/fpm/php.ini
  • Valet sockets: valet8.2.sock, valet8.3.sock, … (one per version)

Need an older version for one project? Continue with the isolation guide.

PHP

Isolating PHP versions

Run a legacy project on PHP 7.4 while the rest of your machine stays on 8.3. Isolation creates a dedicated FPM pool and Nginx config for one site.

Isolate a site

valet isolate {phpVersion} --site={siteName} --secure
Argument / optionMeaning
phpVersionVersion to use, e.g. php@7.4 or 7.4.
--site=Site name when it differs from the directory name.
--secureServe the isolated site over HTTPS with a trusted certificate.
valet isolate php@7.4 --site=example.test --secure
cd ~/sites/legacy && valet isolate 7.4

List and remove isolation

valet isolated                      # URL | SSL | PHP version
valet unisolate                     # current directory back to default PHP
valet unisolate --site=example.test # named site back to default

Pin a version in the project

Add a .valetphprc file to the site root so future valet isolate calls (with no version argument) and valet which-php pick it up automatically.

php@7.4

Run PHP and Composer with the site's version

The valet wrapper proxies these commands through the PHP binary resolved for the current (or given) site:

valet php -v                      # PHP version of this site
valet php --site=legacy artisan   # explicit site
valet composer install            # Composer with that site's PHP
valet composer --site=legacy update

Data & services

Databases

Valet installs MySQL 5.7 with 5.6 compatibility mode and a tuned my.cnf, or MariaDB if you prefer. Both get a dedicated valet user.

Initial configuration

valet install --mariadb
valet db:configure          # set up / reconfigure the valet DB user
valet db:configure --force  # reconfigure even if already set

During configuration you supply the database root password; Valet creates a valet@localhost user with all privileges and stores the credentials in its config.

Every database command

CommandDescription

valet db:drop [name] [-y|--yes]Drop a database (confirmation prompt unless -y).
valet db:reset [name] [-y|--yes]Drop and recreate a database.
valet db:import [name] [dump]Import a .sql or .sql.gz dump with a progress bar.

Name resolution

When you omit the database name, Valet tries the closest Git repository directory name first, then falls back to the current working directory name.

cd ~/sites/blog
valet db:create       # creates database "blog"
valet db:drop blog -y
valet db:reset blog --yes
valet db:export blog            # blog.sql.gz
valet db:export blog --sql      # blog.sql
valet db:import blog backup.sql.gz
v1 command removedvalet db:password <old> <new> existed in 1.x. In v2 use valet db:configure --force to set credentials again.

Guides

Sharing sites publicly

Expose a local site to the internet with an ngrok tunnel — or reach your machine over the LAN.

ngrok setup

Create a free ngrok account, then store your authtoken. Valet checks for ngrok's config before opening a tunnel.

valet ngrok-auth YOUR_AUTHTOKEN
valet share
valet fetch-share-url    # print the current public URL

The ngrok v3 binary is downloaded by valet install into Valet's bin directory. Legacy ~/.ngrok2/ngrok.yml configs are upgraded to ~/.config/ngrok/ngrok.yml automatically.

The wrapper resolves symlinked site names, detects secured sites (port 88 fallback) and starts ngrok with --host-header=rewrite.

LAN access

In v1.x, all sites were reachable from other devices on the network using your machine's IP address and the /valet-sites directory listing:

http://<local-ip-address>/valet-sites
Removed in v2.0/valet-sites was removed in Valet Linux+ 2.0 and may return in a future release. Use valet share for remote access today. LAN access also could not serve TLS certificates because the hostname differs.

Extending Valet

Custom Valet drivers

Serve any PHP framework or CMS by implementing three methods: serves, isStaticFile and frontControllerPath.

Where to put a driver

A sample driver is created during installation. In v2 place global drivers in ~/.config/valet/Drivers (v1 used ~/.valet/Drivers), named FrameworkValetDriver.php. For a single app, create LocalValetDriver.php in the project root.

The three methods

All three receive $sitePath (absolute path), $siteName (host portion, e.g. my-project) and $uri (e.g. /foo/bar).

serves()

Return true when this driver should handle the request.

public function serves($sitePath, $siteName, $uri)
{
    return is_dir($sitePath.'/wp-admin');
}

isStaticFile()

Return the absolute path for static assets, otherwise false. Called only when serves() is true and the URI is not /.

public function isStaticFile($sitePath, $siteName, $uri)
{
    if (file_exists($staticFilePath = $sitePath.'/public/'.$uri)) {
        return $staticFilePath;
    }

    return false;
}

frontControllerPath()

Return the absolute path to the application's front controller.

public function frontControllerPath($sitePath, $siteName, $uri)
{
    return $sitePath.'/public/index.php';
}

Local driver example

A local driver can extend a built-in driver and override only what differs:

class LocalValetDriver extends LaravelValetDriver
{
    public function serves($sitePath, $siteName, $uri)
    {
        return true;
    }

    public function frontControllerPath($sitePath, $siteName, $uri)
    {
        return $sitePath.'/public_html/index.php';
    }
}

Verify detection with valet which after creating the file. No restart is required for local drivers.

Configuration & files

Valet keeps its own state under your user config directory and writes service configs into the system as needed.

The Valet home directory

Since v2.0 the home directory is ~/.config/valet. The v1 ~/.valet directory is migrated automatically on first run.

PathContents
~/.config/valet/config.jsonMain configuration: domain, paths and port.
~/.config/valet/Sites/Symbolic links created by valet link.
~/.config/valet/Nginx/Per-site Nginx configs (plain, secured, isolated, proxy).
~/.config/valet/Certificates/TLS certificates generated by valet secure.
~/.config/valet/CA/Local certificate authority files.
~/.config/valet/Drivers/Your global custom drivers.
~/.config/valet/Log/Nginx, PHP and MySQL logs.
~/.config/valet/bin/Downloaded ngrok binary.

Default configuration

{
  "domain": "test",
  "paths": [],
  "port": "80"
}

A https_port key is added when you run valet port <n> --https. Use valet domain and valet port to read values instead of editing the file by hand.

System locations

  • Global Nginx config stubs: Valet's stubs/ directory (nginx.conf, valet.conf, secure.valet.conf, proxy.valet.conf, isolated variants).
  • PHP-FPM pool: /etc/php/{version}/fpm/pool.d/valet.conf
  • php.ini: /etc/php/{version}/fpm/php.ini
  • Dnsmasq config: /etc/dnsmasq.conf with Valet's .test rule.
  • Resolver / NetworkManager stubs are installed to keep DNS pointed at localhost.

Environment files

Valet's CLI defines VALET_HOME_PATH, VALET_ROOT_PATH and related constants at startup based on your home directory and installation location. Extensions can be dropped into the config directory and are loaded on every command.

The original Valet for Linux.

Valet Linux is a Laravel development environment for Linux minimalists. No Vagrant, no /etc/hosts file. It configures Nginx to run in the background, then uses Dnsmasq to point every *.test request at your local projects — using roughly 7 MB of RAM.

Valet or Homestead?

A lighter kind of local

Homestead ships a complete Ubuntu virtual machine and automated Nginx configuration. Valet Linux installs PHP and a database on your machine and stays extremely fast. Choose Homestead for a full virtualized environment or Windows; choose Valet when you only need PHP + MySQL and value speed.

Never install with rootThe official docs are emphatic: do not run sudo composer global require or install Valet as root. The wrapper uses sudo internally while preserving your $HOME.

Ubuntu notes

Ubuntu 14.04 (Trusty) needs the nginx PPA for HTTP/2 before valet secure will work:

sudo add-apt-repository -y ppa:nginx/stable
sudo apt-get update

LTS releases receive about four years of support; non-LTS about nine months. Development releases are not recommended for reliable issue reporting.

Fedora & SELinux

Fedora 24+ is supported. Valet changes system files, so SELinux must be understood or put into permissive mode:

sudo setenforce 0                 # temporary
# or edit /etc/selinux/config: SELINUX=permissive
valet install --ignore-selinux    # skip the pre-flight check
Check port 80 firstMake sure Apache, Nginx or another process is not already bound to port 80. You can always change it later with valet port 8888.

Original project · setup

Installation

Valet Linux is a global Composer package. Run Composer as your normal user — the valet shell script requests sudo only for the commands that need it.

Install

composer global require cpriego/valet-linux
valet install
ping -c 1 foobar.test    # should answer from 127.0.0.1

The installer configures Nginx, PHP-FPM and Dnsmasq, writes the base config and registers the daemon to start on boot. You never need to run valet install again after the first setup.

Change the TLD and the port

valet domain           # show current TLD (default: test)
valet domain app       # serve *.app instead
valet port             # show HTTP and HTTPS ports
valet port 8888        # change the HTTP port
valet port 8443 --https

Upgrade

composer global update
valet install    # let Valet refresh its config files

Uninstall

valet uninstall removes the Valet pieces. On Ubuntu, the official guide also recommends cleaning up Dnsmasq/NetworkManager and restoring systemd-resolved:

rm -rf /opt/valet
# remove valet-specific files in /etc/NetworkManager/conf.d
# and /etc/NetworkManager/dnsmasq.d
rm -f /etc/dnsmasq.d/valet /etc/dnsmasq.d/options
systemctl enable --now systemd-resolved
# leave dnsmasq-base installed; remove the dnsmasq package only
ln -sf /run/systemd/resolve/resolv.conf /etc/resolv.conf
systemctl restart NetworkManager

Original project · daily use

Serving sites

park serves every project in a directory; link serves one project with a custom name.

park

mkdir -p ~/Sites && cd ~/Sites
valet park
laravel new blog
# open http://blog.test

Every new folder under a parked path automatically becomes folder-name.test. Use valet paths to list roots and valet forget to remove the current one.

link

cd ~/projects/my-app
valet link app-name       # http://app-name.test
valet link blog.app-name  # a subdomain alias
valet links               # list aliases
valet unlink app-name

Links are stored in ~/.valet/Sites. You can serve the same project from multiple names by adding more links.

HTTPS

valet secure blog        # trusted TLS certificate
valet secured blog       # is it secured?
valet unsecure blog      # back to plain HTTP

Restart your browser after securing or unsecuring a site so it trusts the new certificate. See the for manual CA import steps.

Original project · tunnels

Sharing sites publicly

The valet wrapper starts an ngrok tunnel for the current site, copies the public URL to your clipboard and launches a background helper that answers valet fetch-share-url.

cd ~/Sites/blog
valet share             # Ctrl+C to stop
valet fetch-share-url   # print the active public URL
Secured sites cannot be sharedThe original project cannot tunnel a site that has been through valet secure. Run valet unsecure <site> first, or use Valet Linux+ with its newer ngrok integration.

The wrapper resolves symlinked host names, reads the configured domain and port from ~/.valet/config.json, and picks port 88 when the site is secured. It requires jq, xsel and certutil.

Original project · extensibility

Valet drivers

A driver tells Valet how to recognize a project, find static files and locate its front controller. The original project ships {{ legacyDrivers.length }} drivers.

Custom driver

Installing Valet creates ~/.valet/Drivers/SampleValetDriver.php. Implement three methods — serves, isStaticFile and frontControllerPath — then save as FrameworkValetDriver.php in that directory.

<?php
class WordPressValetDriver extends ValetDriver
{
    public function serves($sitePath, $siteName, $uri)
    {
        return is_dir($sitePath.'/wp-admin');
    }

    public function isStaticFile($sitePath, $siteName, $uri)
    {
        if (file_exists($staticFilePath = $sitePath.'/public/'.$uri)) {
            return $staticFilePath;
        }
        return false;
    }

    public function frontControllerPath($sitePath, $siteName, $uri)
    {
        return $sitePath.'/public/index.php';
    }
}

All three methods receive the absolute $sitePath, the host portion $siteName and the request $uri. isStaticFile is only called for non-root requests after serves returns true.

Local driver

For a single application, add LocalValetDriver.php to the project root. It may extend the base driver or an existing one such as LaravelValetDriver:

<?php
class LocalValetDriver extends LaravelValetDriver
{
    public function serves($sitePath, $siteName, $uri)
    {
        return true;
    }

    public function frontControllerPath($sitePath, $siteName, $uri)
    {
        return $sitePath.'/public_html/index.php';
    }
}

Use valet which inside a project to see which driver Valet assigned.

Original project · internals

Configuration & files

Original Valet keeps everything under ~/.valet. The base config is JSON and is owned by your normal user.

~/.valet/config.json

Stores domain (default test), paths and port (default 80). Prefer the valet domain, valet port, valet park and valet forget commands over editing it.

~/.valet/Drivers

Global custom drivers and the generated SampleValetDriver.php.

~/.valet/Sites

Symbolic links created by valet link. Stale links are pruned on every command.

~/.valet/Log & CA

Nginx/PHP-FPM logs and the LaravelValetCASelfSigned certificate authority used by valet secure.

How sudo is used

The bash wrapper elevates uninstall, install, start, restart, stop, unsecure, secure, use, isolate, unisolate plus domain/port when a value is supplied. It calls sudo env HOME=$HOME so Valet writes into your home, not /root.

Other commands run through php cli/valet.php without sudo. share is handled entirely in the wrapper and takes over the terminal while ngrok runs.

PHP version files

The selected global PHP-FPM version is stored in ~/.valet/use_php_version when it differs from the system default. A per-site choice can also be read from a .valetphprc file in the project root.

Both projects

Migrating from Valet Linux to Valet Linux+

Most daily commands are unchanged. The big differences are PHP 8.2+, the moved config home, managed services and a larger CLI.

Before you switch

  1. Back up ~/.valet/config.json, your parked paths and any custom drivers.
  2. Read the — PHP 8.2+ is mandatory.
  3. Uninstall the original package only after your new environment is working: valet uninstall then composer global remove cpriego/valet-linux.

Install the successor

valet uninstall                         # original
composer global remove cpriego/valet-linux
composer global require genesisweb/valet-linux-plus
valet install

On first run, Valet Linux+ migrates the old ~/.valet configuration into ~/.config/valet automatically. Re-park any paths that were not carried over.
